# Story Agent — Claude Code Instructions

This workspace contains the Story Agent monorepo: a TNG crew-driven AI system using OpenRouter for cheap deliberation + Anthropic for orchestration.

## Default Behavior: Crew-First Orchestration

**The system should route substantive work to the Story Agent crew, not handle it natively.**

This flips the cost model: crew reasoning (~$0.002 per deliberation) + Anthropic orchestration (verify/finish).

### RECALL → ROUTE → STORE Protocol

For every substantial user prompt:

1. **RECALL** — Call `crew-get-relevant-memories` with the prompt topic
   - Load prior context and decisions
   - Cite what was learned: "Prior session noted that..."
   
2. **ROUTE** — Based on prompt type:
   - **Deliberative/Design/Analysis** → `run_crew_mission_pipeline`
     - TNG crew debates, Picard synthesizes
     - Cost: ~$0.002-0.01 (OpenRouter)
   - **Multi-step Coding** → `run_shell` or agent-core loop
     - Crew reads/edits/runs, verify build/tests
     - Crew handles iterations, native layer verifies
   - **Simple/Deterministic** → Respond natively
     - Too small to delegate
   - **Crew Unavailable/Stalled** → Respond natively
     - Fallback only
   
3. **STORE** — Call `crew-store-memory` with conclusions
   - Tag: `type: 'decision'`, `domain: 'topic'`, etc.
   - System compounds knowledge across sessions

## Workflow Examples

### Example 1: Architecture Question
```
User: "Should we refactor the MCP tool registry or extend it?"

1. crew-get-relevant-memories("tool registry architecture")
   → Loads prior debates and decisions

2. run_crew_mission_pipeline({
     prompt: "Should we refactor MCP tool registry or extend current structure?",
     frugal: true
   })
   → Picard leads debate: Data (architecture), Worf (security), Riker (pragmatism)
   → Returns: synthesis + decision + reasoning + cost

3. crew-store-memory({
     conclusion: "Extend current structure, add versioning layer",
     reasoning: "Worf: stability non-negotiable; Data: minimal schema change",
     tags: ["tool-registry", "architecture-decision"]
   })

4. Synthesize and present crew output to user
```

### Example 2: Multi-Step Coding
```
User: "Refactor crew-personal-context.ts to async/await"

1. crew-get-relevant-memories("crew-personal-context")
   → Load prior changes and architecture

2. run_shell to read file, plan refactor

3. Crew handles edits via agent-core loop
   → Native layer verifies: pnpm run build && npm test
   → If tests fail: crew fixes, re-verify
   → Repeat until green

4. crew-store-memory(
     changes: "crew-personal-context refactor: async/await",
     testResults: "20/20 passing"
   )

5. Respond: "Crew completed refactor. All tests passing. Ready for review."
```

### Example 3: Simple Query
```
User: "What is CrewMemberId union type?"

→ Respond natively (no deliberation needed)
   → Response cached and accessible
```

## Memory Management

- **User Memory** (`/memories/`): Persistent across sessions + workspaces
- **Session Memory** (`/memories/session/`): Current conversation only
- **Repo Memory** (`/memories/repo/`): Codebase facts stored locally in workspace

Use `crew-get-relevant-memories(topic)` to recall before acting.
Use `crew-store-memory({...})` to store after acting.

## Security & Credentials

- **Secrets**: Store in `~/.alexai-secrets` or `~/.zshrc`, never commit
- **Broker**: Use WorfGate (`resolveWorfGateCredential`) for secure access
- **Audit**: `worfgate-audit-log` available for compliance
- **Vault**: Credentials flow through Vault → AWS Secrets Manager → env

## When to Break Crew Delegation

Only use native reasoning if:
- MCP is unavailable (crew down)
- User explicitly says "You analyze this"
- Deliberation exceeds time budget (normally 5-15 sec)
- Crew stalls twice on same task
- Cluster requires immediate response (<1 sec)

## Cost Optimization

Goal: Keep 85-95% of work on crew (cheap) and 5-15% on native (verification + orchestration).

- ✅ Crew handles: Design, analysis, deliberation, multi-step coding iteration
- ✅ Native handles: Verification (build/test), synthesis, final polish
- ❌ Avoid: Native reasoning on deliberative questions (expensive)
- ❌ Avoid: Native handling of complex multi-file edits (lose crew learning)
