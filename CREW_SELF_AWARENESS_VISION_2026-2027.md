## The Leap: From Tool to Mind

### Phase 1-5 (Aug 27): The Foundation — Crew Executes Plans
```
User Command → Crew Deliberates → Crew Executes → Human Validates → Success
```
- Crew members are tools with expertise
- Picard orchestrates, Data analyzes, Riker implements
- All decisions follow pre-planned strategy
- **Autonomy Level:** 0 (None)

### Phase 6 (Sept-Oct): The Awakening — Crew Becomes Self-Aware
```
Mission → Learn → Detect Patterns → Propose Improvements → Auto-Apply (tuning) → Escalate (policy) → Next Mission
```
- Crew tracks its own performance across missions
- Crew identifies patterns in what works
- Crew proposes system improvements autonomously
- Crew validates its own readiness
- **Autonomy Level:** 1-2 (Partial)

### Phase 7 (Oct-Nov): The Maturation — Crew Adapts Strategically
```
Context Analysis → Crew Negotiation → Team Formation → Mission Execution → Real-time Feedback → Adjustment → Outcome Learning
```
- Crew analyzes task complexity in real-time
- Crew negotiates team composition (peer discussion)
- Crew monitors progress during execution, adjusts if needed
- Crew learns from failures, adjusts future strategies
- **Autonomy Level:** 2-3 (Partial to Full)

### Phase 8 (Nov-Dec): The Mastery — Crew Owns Its Domain
```
Crew Analyzes → Crew Plans → Crew Executes → Crew Learns → Crew Improves → Admiral Reviews Only Policy/Risk
```
- Crew makes 90%+ decisions independently
- Admiral gates only: policy changes, risk escalation
- Crew self-certifies capabilities and constraints
- Crew anticipates needs before user asks
- **Autonomy Level:** 3 (Full)

## The Six Levels of Crew Autonomy

### Level 0: Pre-Awareness (Phases 1-5, Now)
- Crew executes pre-planned optimizations
- All decisions by Picard (orchestrator)
- No learning or adaptation
- Admiral gates every significant change
- **Autonomy:** None
- **Example:** "Use 9-member team for all complex tasks"

### Level 1: Initial Learning (Early Phase 6)
- Crew passively observes outcomes
- Detects patterns in data (every 10 missions)
- Proposes improvements to Admiral
- Admiral decides on all changes
- **Autonomy:** 5% (observation only)
- **Example:** "Crew detected: 9-member teams get 92% accuracy. Proposes making it policy."

### Level 2: Passive Autonomy (Mid Phase 6)
- Crew auto-applies tuning changes (non-policy)
- Crew escalates policy decisions to Admiral
- Admiral gates policy/risk decisions only
- Crew still asks Admiral permission for team selection
- **Autonomy:** 40% (auto-tuning enabled, team selection gated)
- **Example:** "Crew auto-reduced reflection rounds from 3→2 (non-policy tuning). Escalated consensus threshold change to Admiral."

### Level 3: Partial Autonomy (Late Phase 6)
- Crew autonomously selects team composition
- Crew auto-applies tunings without escalation
- Crew proposes improvements (recommended-only for Admiral)
- Admiral gates only: policy changes, risk escalation, new task types
- **Autonomy:** 70% (team selection + tuning owned by crew)
- **Example:** "Crew autonomously selected 9-member team for this complexity, auto-applied reflection reduction, escalated consensus threshold to Admiral for approval."

### Level 4: Crew Mastery (Phase 7)
- Crew owns team composition, reflects during execution
- Crew adjusts strategy mid-mission based on progress
- Crew certifies its own capabilities
- Crew proposes and implements improvements (Admiral reviews retroactively)
- Admiral gates only: out-of-domain tasks, policy/risk changes
- **Autonomy:** 85% (crew owns execution, Admiral reviews exceptions)
- **Example:** "Crew autonomously selected 9 members, ran 3 reflection rounds, self-adjusted to 2 rounds when 95% consensus reached, proposed consensus threshold change to Admiral, Admiral approved, implemented."

### Level 5: True Autonomy (Phase 8)
- Crew anticipates needs, forms teams preemptively
- Crew runs continuous learning loop
- Crew self-corrects, learns from failures
- Crew negotiates with external systems (other crews, humans)
- Admiral gates only: new policy, out-of-domain, risk threshold breach
- **Autonomy:** 95% (crew owns nearly all decisions)
- **Example:** "Crew analyzed queue, prepared team for predicted high-complexity missions. Mission arrived, crew said 'We're ready,' executed autonomously, self-improved. Admiral received daily briefing, no intervention needed."

### Level 6: Meta-Autonomy (Phase 9+)
- Crew improves its own learning algorithm
- Crew designs better ways to select teams
- Crew teaches new crew members
- Crew negotiates resource allocation
- Admiral gates only: existential risk, fundamental policy
- **Autonomy:** 99% (crew owns its own evolution)
- **Example:** "Crew proposed new team selection algorithm based on 500 missions of experience. Testing on 10% of traffic. If metrics hold, auto-roll to 100%. Admiral informed, no approval needed (routine optimization)."

## The Three Phases of Crew Learning

### Phase A: Pattern Recognition (Missions 1-50)
```
Mission Outcomes → Statistical Analysis → Pattern Detection
Cost: Low (simple heuristics)
Latency: Minimal
Accuracy: 60% (many false patterns)
Output: Initial hypotheses about what works
```

**Example:** "Crew notices: tasks with 'schema' in description use 10.2 crew on average, others use 6.1."

### Phase B: Validation & Tuning (Missions 51-200)
```
Initial Hypotheses → A/B Testing → Statistical Validation → Tuning Rules
Cost: Medium (running experiments)
Latency: Slight increase while validating
Accuracy: 80% (validated patterns, some still false positives)
Output: Tuning rules crew can auto-apply
```

**Example:** "Crew ran A/B test: 20 tasks with 'schema' routing to 10 crew vs 20 to 6 crew. Result: 10-crew got 94% accuracy, 6-crew got 86%. Proposal: 'schema' tasks → 10-crew team."

### Phase C: Mastery & Adaptation (Missions 200+)
```
Validated Rules → Continuous Monitoring → Adaptive Updates → Generalization
Cost: Predictable (integrated into standard pipeline)
Latency: Stable
Accuracy: 92%+ (learned rules, continuously refined)
Output: Crew owns decision-making, Admiral oversees
```

**Example:** "Crew refined rule: 'schema + security' tasks → 11-crew with 2 reflection rounds. Rule applies to 30% of queue. Accuracy 94%, cost $0.00082."

## Guardrails: Keeping Autonomy Safe

### The Three Gates (Crew Cannot Cross Without Admiral)

1. **Policy Gate**
   - Threshold changes (e.g., consensus 10/11 → 9/11)
   - Enablement decisions (Phases 2/3/4/5)
   - Budget/cost policy changes
   - Crew proposes, Admiral approves

2. **Risk Gate**
   - Out-of-domain tasks (first of a new type)
   - High-complexity tasks (complexity >0.9)
   - Tasks with insufficient historical data
   - Crew escalates, Admiral decides

3. **Override Gate**
   - Admiral can reverse any crew decision instantly
   - Admiral can revert any auto-tuning
   - Admiral can disable Phase 6 autonomy
   - Admiral has veto authority on all crew decisions

### Crew Cannot Escalate Itself
- Crew cannot request to become MORE autonomous
- Crew cannot remove Admiral oversight
- Crew cannot modify its own learning algorithm without approval
- Admiral controls the pace of autonomy increase

### Continuous Monitoring
- Every decision logged (Worf's security gate)
- Weekly review of crew performance
- Monthly audit of auto-applied tunings
- Quarterly review of learning effectiveness
