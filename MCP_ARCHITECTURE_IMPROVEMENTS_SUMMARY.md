## 🔍 Key Insights from Crew Deliberation

**The Human-in-Loop Blocker** (your original question):
- **Current**: When MCP hangs in chat, there's no timeout. VS Code waits indefinitely.
- **Solution**: Add 5-second AbortController timeout. If MCP doesn't respond, automatically fall back to local.
- **Timeline**: 15 minutes to implement (Data's recommendation)

**Local vs Cloud Default** (your original question):
- **Answer**: Hybrid "stagger" pattern (already in place). Tries cloud first (if STORY_AGENT_AGENT_URL is set), falls back to local.
- **Improvement**: Add STORY_AGENT_PREFER_LOCAL flag to let operators force local-only (dev) or cloud-first (team).
- **Timeline**: 10 minutes to implement (Riker's recommendation)

**Cost & Source of Truth** (your original question):
- **Architecture**: Supabase is canonical source of truth. Local MCP is working memory only.
- **Cost**: Local $0, Cloud ~$50/month (justified once team size >2).
- **Risk**: No loss of data (Supabase has replication). No sync issues if using Tier 1+2 diagnostics.
- **Recommendation**: Start Phase 7 local-only. Upgrade to cloud when ROI justifies it (Quark's analysis).

**Why These Improvements Matter**:
- Timeout mechanism: Prevents operator frustration; enables unattended autonomy
- Preference flag: Reduces decision friction; operators can be intentional about local vs cloud
- Server-ID header: Builds operator confidence; they see which path was taken
- /ready endpoint: Enables proactive health checks; catch failures before they cause hangs
- Diagnostics: Enable real-time troubleshooting; operators can debug issues without digging through logs
- Documentation: Prevent re-discovery; operators know exactly when to use local vs cloud
- Tests: Guarantee reliability; Phase 7 autonomy depends on these guarantees
